- 날짜: 2026-11-09
- 상태: 목 구현 완료, 리뷰 통과(e16fd07, 실연결 대기) (스펙 rev 63 /setup "확인과 완료"). 실제 슬랙 게시는 #3 토큰 뒤.

## 스펙

"확인과 완료: 대시보드 미리보기 -> [시작하기] -> 위키에 커밋 하나(log.md에 세팅 완료 한 줄 포함), 태블릿이 대시보드로 자동 전환, `#가족` 채널에 환영 메시지와 사용 예시 3개 게시"

## 결정

### 1. 위키 커밋의 "세팅 완료" 한 줄
커밋은 이미 하나(`FsWikiRepository.applySetup`)였다. 요약 문구를 스펙대로 `세팅 완료: 햇살네 (구성원 4명, 기념일 2건)`로 바꿨다(옛 `가족 세팅: …`). log.md 줄은 `- 2026-10-30 20:00 [setup] 세팅 완료: … (by setup)`, 커밋 제목은 `[setup] 세팅 완료: …`. 기존 단언(core 테스트, e2e, wiki-format.md, 0004)을 같이 고쳤다.

### 2. 태블릿 전환 간격
`useDashboardState`가 상태에 따라 간격을 고른다(`lib/poll-interval.ts`): 세팅 화면(needsSetup) **5초**, 대시보드 60초 그대로. [시작하기] 뒤 5초(+요청 시간) 안에 바뀐다. 세팅 화면에서만 5초라 부하는 세팅 중인 태블릿 한 대뿐이다. 화면 디자인은 그대로(완료 화면의 "태블릿이 1분 안에 바뀝니다" 문구는 상한으로는 여전히 맞아 두었다).

### 3. 환영 메시지: outbox 파일 + 봇이 처리
- 대시보드(Next)와 봇은 다른 프로세스이고 대시보드에는 슬랙 클라이언트가 없다. 0007과 같은 방식으로 `HSH_STATE_DIR`(기본 `~/.homesweethome/state`, 위키 밖) 아래 `notice/`에 파일로 넘긴다.
- 포트 `SetupNoticeStore`(`@hsh/core` `setup-notice.ts`: put·list·claim·release·complete·expire), 파일 구현 `FsSetupNoticeStore`(`@hsh/core/node`). 상태 폴더 해석은 #19 코드(`ConfigProvider.stateDir`)를 그대로 쓴다.
- 알림 내용: `{id, familyId, completedAt, version}`뿐. 슬랙 ID·이름·생일 없음(구성원은 봇이 게시 때 위키에서 읽는다).
- 대시보드: `runSetup`이 위키 쓰기 성공 뒤 `notice.put`(주입). **넣기 실패는 세팅 성공을 막지 않고** 서버 로그만(환영 메시지만 빠짐). 상태 폴더 설정이 잘못돼도 같다.
- 봇: `apps/bot/src/welcome/`. `WelcomeWorker`가 5초마다 확인 -> claim -> 위키 읽기 -> `chat.postMessage`(기존 `SlackChatClient` 타입 재사용, `slackWelcomePoster`) -> complete. 토큰은 0003 §5대로 **InstallationStore.fetchInstallation()의 bot.token**으로 게시 때마다 받아 클라이언트를 만든다(env 직접 참조 없음). 메시지 조립은 순수 함수 `buildWelcomeMessage`(`message.ts`).
- 메시지: 가족 이름 환영 + 슬랙 연결된 구성원 멘션(`<@U…>`, slackId 있는 사람만, 최대 12명) + "이렇게 말해 보세요" 예시 **정확히 3개**(일정 넣기·장보기/할 일 추가·질문, 일정은 아이 이름·질문은 보호자 이름 사용, 이름이 없으면 이름 없는 문구) + "확인 버튼을 누르면 위키에 들어가요" 안내. 이름·가족 이름은 mrkdwn 이스케이프, 코드 표시 안의 백틱·줄바꿈 제거.

### 중복 방지
- 쓰기는 0007과 같은 "임시 파일 + `link(2)`" 배타 생성(Windows는 NTFS 필요, EPERM/EBUSY 한 번 재시도).
- `claim`은 `<id>.claim-<n>.json`을 번호를 올려 가며 배타 생성한다. 두 봇이 동시에 이어받으려 해도 같은 번호를 만드는 쪽은 하나(테스트: 저장소 4개로 12번 동시 claim -> 성공 1). 번호를 올리는 방식이라 "지우고 다시 만들기" 경쟁이 없다.
- 게시 직후 `complete`: `<id>.done`(배타) -> 알림 파일 삭제. done이 있으면 어떤 claim도 실패하고 list에도 안 나온다. 목록을 읽어 둔 다른 봇이 늦게 claim해도 알림 존재·done을 다시 확인해 실패한다.
- 봇 두 개·재시작·tick 겹침(봇 안에서는 한 번에 하나)에도 한 번만 게시된다(테스트).
- 게시는 했는데 complete 기록이 실패하면 봇은 다시 게시하지 않고 기록만 재시도한다.

### 슬랙 클라이언트 설정 (리뷰 반영)
`postMessage`는 멱등이 아니다. `WebClient` 기본값(타임아웃 없음, 최대 30분 자동 재시도, 레이트리밋 대기)이면 타임아웃 뒤 재시도로 같은 글이 두 번 올라가거나 worker가 오래 멈춘다. 그래서 `timeout: 10_000`, `retryConfig: { retries: 0 }`, `rejectRateLimitedCalls: true`로 만들고(`WELCOME_CLIENT_OPTIONS`), 재시도는 worker의 백오프에서만 한다.

### claim 토큰 (리뷰 반영)
`claim`은 번호(토큰)를 돌려주고 `release(id, token)`은 **자기 번호의 반납 표식만** 만든다. A가 임대(5분)를 넘겨 B가 claim-2를 잡은 뒤 A가 늦게 release해도 B의 claim은 유지된다(테스트). `complete`는 게시했다는 사실이라 토큰과 무관하게 done을 남긴다(이어받은 쪽이 아직 게시 전이면 멈추게 된다). 삭제는 알림 파일 -> claim -> done 순(done이 마지막). 파일 하나를 못 읽어도(EACCES 등) list는 그 파일만 건너뛰고 경고하며, worker의 tick 경고는 같은 메시지가 반복되면 바뀔 때만 남긴다. 가족 이름의 서식 기호(`* _ ~` 백틱)는 굵게를 깨지 않도록 뺀다. 완료 화면 문구는 "태블릿이 곧 대시보드로 바뀝니다"로 바꿨다(문구만).

### 실패 처리
- `SLACK_FAMILY_CHANNEL`이 없으면 경고 한 번 + 알림을 그대로 둔다(채널 설정 후 재시작하면 게시).
- 게시 실패(채널에 봇 없음, 레이트리밋 등)·위키 읽기 실패: claim을 반납(release)하고 5초부터 두 배씩(상한 10분) 늘려 다시 시도(봇 메모리).
- **24시간**: `completedAt`부터 24시간이 지난 알림은 게시하지 않고 지운다(`expire`, 매 확인마다). 봇이 꺼져 있다가 24시간 안에 켜지면 게시한다. 오래된 환영 메시지가 갑자기 올라오는 것을 막는 상한이다.
- 끝난 알림의 claim·done 찌꺼기와 죽은 임시 파일은 1시간 뒤 정리.
- 봇이 claim한 채 죽으면 5분(임대) 뒤 다른 봇·재시작한 봇이 이어받는다. 이 5분 구멍과 "게시는 했는데 complete 기록 전에 죽음"은 드물게 환영 메시지가 두 번 올라갈 수 있는 한계다(최대 한 번 더, 알림이 사라지는 쪽(분실)보다 중복을 택함).

## 대안과 버리는 이유
- **봇이 위키를 감시(git pull·파일 변화로 setup 커밋을 찾기)**: 위키에 "환영 보냄" 표식이 없어 재시작·두 번째 봇에서 중복·누락을 가릴 수 없고, 위키에 상태를 쓰면 위키 쓰기 규칙(apply만)과 충돌한다. 세팅 커밋이 push 안 된 로컬일 수도 있다. 알림 상자가 "한 번만"을 파일 연산 하나로 보장한다.
- **대시보드가 슬랙을 직접 호출**: 봇 토큰을 Next 서버에 두고 슬랙 클라이언트를 하나 더 만든다. 0003의 "입력·외부 서비스는 어댑터 뒤" 원칙과 프로세스 분리에 어긋난다.
- **대시보드가 봇에 HTTP로 알림**: 봇이 꺼져 있으면 유실. 파일은 봇이 켜질 때까지 남는다(24시간).
- **rename으로 쓰기**: 덮어써서 claim이 두 번 성공할 수 있다(0007).

## 필요한 값 (실연결)
`SLACK_BOT_TOKEN`, `SLACK_APP_TOKEN`, `SLACK_FAMILY_CHANNEL`(채널 id, C로 시작), `HSH_STATE_DIR`(선택, 대시보드·봇이 같은 값). 슬랙 앱 봇 스코프 `chat:write`, 봇이 #가족 채널에 초대돼 있어야 한다(없으면 `not_in_channel`로 실패하고 재시도). `.env.example`은 권한상 열지 못했다.
