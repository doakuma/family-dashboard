# 0007. 슬랙 연결 코드 + DM 매핑 (#19)

- 날짜: 2026-11-09
- 상태: 목 구현 완료, 리뷰 대기 (스펙 rev 63 /setup 3단계 기준). 실제 슬랙 연결은 #3 토큰 뒤.

## 문제

스펙: "구성원마다 6자리 연결 코드를 보여주고, 본인이 슬랙에서 봇에게 `연결 482913`을 DM하면 슬랙 ID가 자동 매핑. 아이는 건너뛸 수 있음."
세팅 마법사는 끝(`POST /api/setup/complete`)까지 위키에 아무것도 쓰지 않고(0004), 봇과 대시보드는 다른 프로세스(같은 노트북, PM2)다.
그래서 "마법사가 발급한 코드"를 "봇이 받은 DM"이 알아볼 방법과, 마법사가 끝날 때 그 결과를 읽을 방법이 필요하다.

## 결정

### 프로세스 간 저장소: 포트 `ConnectCodeStore` + 파일 구현 `FsConnectCodeStore`
- 포트와 순수 함수(코드 형식, `연결 <6자리>` 파싱, 코드 생성)는 `@hsh/core`(`connect-code.ts`), 파일 구현은 `@hsh/core/node`. 서비스에서는 DB 구현으로 바꾼다(0003의 방식).
- 상태 폴더는 `ConfigProvider`의 새 키 `stateDir`(환경 변수 `HSH_STATE_DIR`, 없으면 `~/.homesweethome/state`). **위키 레포 안에 두지 않는다**(위키에 임시 코드·슬랙 ID 후보가 커밋되면 안 됨). 안에 `connect/` 폴더, 폴더·파일 권한 0700/0600.
- 코드 하나당 파일 둘: `<코드>.json`(발급 기록: code, memberKey, name, role, scope, issuedAt, expiresAt) · `<코드>.claim.json`(연결 기록: slackId, claimedAt).
- **쓰기는 "임시 파일에 다 쓰고 `link(2)`로 최종 이름 만들기"**. 스펙의 "임시 파일 + rename"과 같은 목적(반쯤 쓴 파일이 안 보임)이면서, rename과 달리 이미 있으면 EEXIST로 실패하므로 **배타 생성**이 된다. 이 하나로 (1) 두 프로세스가 같은 코드를 만드는 것, (2) 같은 코드를 두 번·동시에 claim하는 것을 막는다(테스트: 저장소 4개로 12번 동시 claim -> 성공 1).
- 코드는 `crypto.randomInt`로 6자리, 활성 코드와 겹치면 다시 뽑는다. 같은 범위·memberKey로 다시 발급하면 이전 코드와 그 연결 기록을 지운다. 발급할 때마다 만료·깨진·짝 없는 파일을 정리한다. 활성 코드 상한 40개(발급 API 남용 방지, 초과 시 429).
- 수명: 연결 전 코드 **30분**. 연결된 코드는 마법사를 끝낼 때까지 남아야 하므로 claim부터 **24시간**.
- `scope`는 지금 `"setup"` 하나. 세팅 뒤 재연결(/settings)은 #22가 값을 더해 쓴다(구현하지 않음).
- 같은 슬랙 계정이 같은 범위에서 이미 다른 구성원 코드를 썼으면 claim이 `slack_taken`(그 이름 포함)으로 거절한다. 동시에 두 코드를 보내는 경쟁은 저장소 검사를 빠져나갈 수 있어, 마법사 완료가 한 번 더 막는다(422).

### 대시보드 API (#17 방어 그대로)
- 순서: 폼 출처(403) -> 세션 via=setup(401) -> 본문 형식·크기(415·411·413·400) -> zod(422) -> 세팅이 필요한지(끝났으면 409). 공통 관문 `lib/setup/guard.ts`(의존을 인자로 받아 단위 시험), 완료 API도 같은 관문을 쓰도록 옮겼다.
- `POST /api/setup/connect` `{memberKey, name, role}` -> `{code, expiresAt}` (본문 1KB 상한, 여분 필드 거부).
- `POST /api/setup/connect/status` `{codes:[…]}` -> `{states:{코드:pending|connected|expired}}`. 모르는 코드도 expired(존재 여부를 구분하지 않음). **슬랙 ID는 응답 어디에도 없다.**
- `POST /api/setup/complete`에 `connectCodes: [{memberId, memberKey, code}]`를 더했다. 서버가 저장소의 연결 기록에서 slackId를 찾아 구성원에 넣는다.
  - **클라이언트가 보낸 `setup.members[].slackId`는 조용히 지우지 않고 422로 거부한다**(경로 `members.N.slackId`). 이유: 조작·잘못된 클라이언트를 드러내고, "받았는데 무시됨"으로 오해하지 않게. 정상 화면은 slackId를 보내지 않는다.
  - 코드가 다른 구성원의 것(memberKey 불일치), 없는 구성원 id, 같은 구성원·코드 중복, 한 슬랙 계정이 두 구성원 -> 422.
  - **코드를 받았지만 연결이 안 끝난(DM 전·만료·없음) 구성원은 막지 않고 slackId 없이 만들고**, 응답에 `unlinked: [구성원 id]`(슬랙 ID 아님)로 알린다. 완료 화면이 이름으로 "연결을 끝내지 못한 구성원"을 보여 준다.
  - 위키 쓰기가 성공한 뒤에만 setup 범위 코드를 전부 폐기한다(실패하면 남겨 다시 시도할 수 있게). 폐기 실패는 로그만(세팅은 성공, 코드는 만료로 사라진다).

### 마법사 3단계(SlackStep)
- 구성원마다 [코드 받기] -> `ConnectCodeSlot`에 코드 + "슬랙에서 봇에게 `연결 123456` 라고 DM으로 보내세요. 30분 안에…" -> **3단계가 보이는 동안만**(훅이 단계와 함께 사라짐) 3초 간격 상태 폴링 -> "✓ 연결됨". 탭이 가려지면 쉬고 다시 보이면 바로 확인, 연결됨·만료인 코드는 더 묻지 않는다. 세션이 끝나면(401·409) 폴링을 멈추고 안내.
- 아이는 건너뛰는 게 기본(안내 문구, 버튼은 보조 모양). 아무것도 안 해도 "건너뛰기"로 진행. 코드를 하나라도 받았으면 버튼이 "다음".
- `connectCode`는 draft(sessionStorage)에 저장해 새로고침해도 유지. 이름·역할을 바꾸면 낡은 코드는 버린다(코드에 이름이 들어 있어서).
- 접근성(0004 기준): 모든 버튼에 구성원 이름이 든 라벨(`엄마 연결 코드 받기`), 48px(e2e가 검사), 상태 변화는 `role=status aria-live=polite` 문구로 알림("엄마 님이 슬랙에 연결됐어요"), 상태는 글자(✓ 연결됨, 시간이 지났어요)로도 표시해 색만으로 구분하지 않는다. 색은 토큰만, 새 CSS 없음.

### 봇 (`apps/bot/src/connect/`)
- `ConnectHandler`가 슬랙과 무관하게 `store(claim·revoke)`와 `ui(post·whisper)` 포트만 받는다. 슬랙 사용은 `index.ts`의 message 리스너에서 `toConversationMessage` **직후, 대화 흐름(LLM)보다 먼저** `tryHandle`을 부르는 것뿐이다(코드를 LLM에 보내지 않음).
- 파싱: 글 어디서든 `연결` + 공백(없어도, 전각 공백 포함)·콜론·전각 숫자 + 6자리(7자리 이상이면 코드 아님). 글 어디서든 잡는 이유: 채널에 "연결 482913 이거 맞아?"처럼 올려도 코드를 지워야 해서.
- **DM에서만 연결**. 성공: "'하늘'(으)로 연결했어요. 세팅을 마치면 이 슬랙 계정으로 쓸 수 있어요."
- **채널에 올린 코드**: 연결하지 않고 그 코드를 무효화(revoke), 보낸 사람에게만(ephemeral) "코드는 봇 DM으로 보내 주세요. 채널에 보인 코드는 지웠으니 새 코드를 받아 주세요." 대화 흐름으로 넘기지 않는다. 채널에 공개 답글은 달지 않는다.
- 틀림·만료·이미 다른 계정이 씀은 **같은 문구**("코드가 맞지 않거나 시간이 지났어요. 세팅 화면에서 새 코드를 받아 다시 보내 주세요."). 슬랙 사용자별 **연속 실패 5회면 15분 잠금**(봇 메모리, 첫 실패부터 15분 안의 것만 셈, 성공하면 초기화). 잠긴 동안은 맞는 코드도 저장소를 부르지 않는다.
- 이 계정이 이미 다른 구성원으로 연결됐으면 거부하고 이름을 알린다("이 슬랙 계정은 이미 '엄마'(으)로 연결돼 있어요…"). 이건 코드가 맞았다는 뜻이라 실패 횟수에 세지 않는다. 같은 계정이 같은 코드를 또 보내면 "이미 '하늘'(으)로 연결돼 있어요".
- 봇 글·수정·bot_id 글은 `toConversationMessage`가 이미 걸러 준다. 코드는 로그에 남기지 않는다.

## 대안과 버리는 이유
- 위키(`family-wiki`)에 임시 코드를 쓰기: 마법사가 끝나기 전엔 위키에 쓰지 않는다는 0004와 충돌, 커밋에 남는다.
- 대시보드가 봇에 HTTP로 코드를 등록: 봇에 서버를 열어야 하고, 봇이 꺼져 있으면 발급이 실패한다. 같은 노트북이라 공유 폴더가 더 단순하다.
- rename으로 쓰기: 이미 있어도 덮어써서 claim이 두 번 성공할 수 있다. link가 같은 원자성에 배타성을 더한다.
- 클라이언트가 보낸 slackId를 무시(제거): 조용히 넘어가 조작 시도가 안 보인다. 422로 거부.
- 연결 안 끝난 코드가 있으면 완료를 막기: 폰에서 코드만 받고 DM을 못 보낸 사람이 마지막에 막힌다. 연결은 나중에 할 수 있으니(#22) 알리고 진행한다.

## 스펙과 다른 점 / 스펙에 없어 정한 것 (오너 확인 필요)
1. 연결 코드를 받았지만 연결을 끝내지 못한 구성원은 **완료를 막지 않고** 슬랙 ID 없이 만들고 알린다(스펙은 침묵).
2. 연결된 코드가 **24시간** 살아 있다(스펙은 코드 수명 미정, 30분은 내가 정함). 마법사를 하루 넘게 열어 두면 연결이 풀린다.
3. 같은 슬랙 계정이 같은 세팅에서 두 구성원에 연결되는 것을 거부한다(스펙은 침묵).
4. 슬랙 사용자별 실패 5회·15분 잠금은 지시대로 봇 **메모리**라 봇이 재시작하면 풀린다. 코드가 6자리(100만 가지)·30분 수명·활성 코드 40개 이하라 무차별 대입 위험은 낮지만, 재시작으로 풀리는 점은 알려 둔다.
5. 위키 쓰기와 별개로 상태 폴더라는 **새 저장 위치**(`HSH_STATE_DIR`)가 생겼다. 스펙의 "환경" 절에 한 줄 필요. `.env.example`은 권한상 이 작업에서 열지 못해 `HSH_STATE_DIR`(선택)를 못 적었다.

## 못 한 것 / 남은 문제
- 실제 슬랙 DM 수신·ephemeral 동작은 #3 토큰 뒤에 확인한다(`im:history`, 이벤트 `message.im`, App Home의 Messages 탭 켜기, 채널 ephemeral은 봇이 채널에 있어야 함).
- 세팅 완료 처리(#20 환영 메시지), 세팅 뒤 재연결(#22)은 하지 않았다.
- 대시보드는 슬랙 계정이 실제로 그 워크스페이스 구성원인지 확인하지 않는다(봇이 받은 DM의 `user`를 믿는다).
