# 0011. 기상청 날씨 어댑터 + 30분 캐시 (#12)

- 날짜: 2026-11-09
- 상태: 목 구현 완료, 리뷰 대기 (스펙 rev 63). 실제 호출은 #26 키 뒤. 키·네트워크 없이 주입한 fetch 목 + 공식 응답 형식의 지어낸 예시(`packages/core/src/weather/__fixtures__/`)로만 시험했다.

## 구조

- core `weather/kma.ts`: 순수 함수(브라우저 안전). 발표 시각, 응답 봉투 해석, 단기·중기 파싱, 합치기.
- core `weather/kma-source.ts`: `KmaWeatherSource`(fetch·now·region 주입)와 `cachedByRegion`(지역별 캐시). `WeatherSource` 포트는 그대로.
- 대시보드 `lib/weather.ts`의 `createWeatherSource`: 어떤 걸 쓸지만 고른다. 위키는 읽기만(config.md).
- 환경 변수 `KMA_SERVICE_KEY`(공공데이터포털 '일반 인증키(Decoding)'). `ConfigProvider`의 `kmaServiceKey`로 읽는다(앱 코드가 process.env를 직접 읽지 않는 규칙). `.env.example`은 오너가 추가.

## 발표 시각 (모두 서울 기준 입력 Date)

- 단기 `base_time`: 02·05·08·11·14·17·20·23시, **정각 + 10분**부터 사용. 02:10 전이면 전날 2300. (자정·월말·연말·윤일 테스트)
- 중기 `tmFc`: 0600·1800, **정각 + 30분**부터 사용. 06:30 전이면 전날 1800. 중기가 단기보다 늦게 올라온다는 보수적 가정이라 실연결에서 줄일 수 있다.
- 막 발표된 직후 `NO_DATA`(03)면 직전 발표(단기 3시간 전, 중기 12시간 전 시각으로 다시 계산)로 한 번 더 시도한다.

## 아이콘 규칙

- 단기: 낮(06~21시)만 본다. 낮에 PTY가 0이 아닌 시각이 하나라도 있으면 강수 아이콘(눈·비/눈 > 비 > 소나기). 없으면 낮 SKY 평균(맑음 0, 구름많음 1, 흐림 2): 0.5 미만 맑음, 1.5 미만 구름 조금(partly), 그 이상 흐림. 한 시각의 약한 비도 비로 본다(우산을 빠뜨리는 쪽보다 낫다고 판단, 강수확률은 따로 보여 준다).
- 낮 자료가 없는 날: 오늘이면 전체 시각으로 대신하고, 오늘이 아니면 뺀다(단기 끝의 0시 한 칸이 중기를 가리지 않게).
- 비/눈(진눈깨비)은 `snow`로 보여 준다(WeatherIcon에 진눈깨비가 없고, 미끄러움 주의가 더 중요).
- 중기 `wf` 문자열: "눈" 포함 -> snow, "소나기" -> shower, "비" -> rain, "맑"→sunny, "구름"→partly, "흐"→cloudy. 모르는 문자열은 cloudy + 경고 로그. 오전/오후가 있으면 강수가 있는 쪽 중 가장 센 것, 없으면 오후 값. 강수확률은 오전·오후 중 큰 값.

## 기온·강수확률

- 단기: TMN/TMX, 없으면 그날 TMP의 최저/최고. **오늘은 늦은 발표분(05시 이후)에 TMN이 없을 수 있어 TMP 최저로 대신하므로 실제 아침 최저보다 높게 나올 수 있다**(실연결에서 확인). POP는 그날 최대. 값은 반올림해 정수.
- 중기: `taMin{n}`/`taMax{n}`. 하나라도 없으면 그날은 뺀다. `-999` 같은 결측 표시는 없는 값으로 본다.
- 중기 n은 **tmFc 날짜 기준 n일 뒤**. 응답에 있는 n(3~10)의 키만 쓴다. 3~7은 Am/Pm, 8~10은 단일 키 형태 둘 다 처리.

## 합치기

오늘~+6일 7칸, 날짜마다 단기 우선, 없으면 중기, 둘 다 없으면 그날은 뺀다. `WeatherStrip`은 7칸 고정 grid에 있는 만큼만 그린다(왼쪽부터, 라벨은 날짜 차이로 계산해 틀리지 않음). 알려진 틈: 23:10~24:00(오늘 자료가 없는 발표분)에는 오늘 칸이 없다.

## 오류 구분

- `resultCode` 03 -> `no_data`, 그 외 ≠00 -> `api`. dataType=JSON이어도 인증 오류는 XML(`<OpenAPI_ServiceResponse>`, 예 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`)로 오므로 `<`로 시작하면 `auth`. HTTP 오류는 본문이 XML이면 그쪽 설명 우선, 아니면 `http`. 이 밖에 `network`·`timeout`(요청당 10초 `AbortSignal.timeout`)·`format`·`no_region`.
- **오류 메시지·경고에 serviceKey와 URL을 싣지 않는다**: 원래 오류 메시지는 버리고 우리 문구만 쓴다(테스트: 키가 섞인 오류 5종).

## 부분 성공

단기 1회 + 중기 2회(육상·기온). 중기는 육상과 기온이 둘 다 와야 쓴다. 단기만/중기만 성공해도 그것으로 돌려주고 경고를 남긴다. 둘 다 실패하거나 결과가 비었는데 실패가 있으면 던진다.

## 캐시·실패 정책

- 키 = `nx,ny,midLandRegId,midTaRegId`. 요청마다 지역을 읽어 키를 만들므로 #22 /settings에서 지역이 바뀌면 TTL 안이어도 다음 요청에 새 지역으로 받는다. 이전 지역 항목은 최근 4개까지 남긴다.
- TTL 30분. 같은 지역의 동시 요청은 하나로 합친다.
- 실패하면 같은 지역의 직전 성공값을 돌려주되 **6시간**을 넘으면 던진다(낡은 예보를 계속 보여 주지 않는다). **5분** 동안은 다시 시도하지 않는다(그 사이 요청은 직전 값, 없으면 같은 오류). 처음부터 실패하면 던지고(대시보드는 "날씨 정보를 가져오지 못했어요") 5분 뒤 재시도.
- 키가 없거나 config에 좌표가 4개 다 없으면 예시 날씨(`SampleWeatherSource`). 예전에는 예시도 30분 캐시했지만 계산이 싸고 자정에 날짜가 안 넘어가는 문제가 있어 캐시하지 않는다.

## 실연결 때 확인할 것 (#26 키 뒤)

1. 실제 응답과 fixture 대조(필드·타입: `fcstValue`가 문자열인지, `items.item`이 단일일 때 객체인지).
2. 중기 n 범위와 키 이름(Am/Pm 경계, 8일 이후 단일 키).
3. 단기 `base_time` 여유(10분)와 중기 여유(30분)가 맞는지. NO_DATA가 자주 나면 여유를 늘린다.
4. 오늘 TMN 누락 시 표시 기온이 실제와 어긋나는지, 필요하면 02시 발표분을 따로 받아 오늘 최저·최고만 보충.
5. `numOfRows=1500`이 단기 응답 전체를 담는지(`totalCount` 확인).
6. 하루 호출량(지역 하나 기준 30분마다 3회 = 144회/일)이 무료 한도 안인지, 서버 시각이 서울이 아니어도 계산이 맞는지(코드는 UTC에서 +9h 고정).
